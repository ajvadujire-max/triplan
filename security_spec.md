# Security Specification: TripPro Travel Planner

## 1. Data Invariants
- **User Ownership:** All Trips, FinanceAccounts, and CashbookEntries are scoped to `/users/{userId}/` where `userId` is the authenticated User ID (`request.auth.uid`). No user can access or write to another user's path.
- **Trip Validity:** A trip must have a valid name, destination, purpose, start date, end date, and status.
- **Financial Balances:** Balance and expense amounts must be valid numbers.
- **Audit Logging:** Every CashbookEntry must contain a timestamped `auditTrail` generated by the app.

---

## 2. The "Dirty Dozen" Payloads (Exploit Attempts)

1. **Identity Spoofing (Trip Creation under other user):**
   - Attempting to create a trip under `users/attacker_uid/trips/trip_1` where the authenticated UID is `victim_uid`.
   - Expected: `PERMISSION_DENIED`

2. **Cross-Tenant Read (Unauthorized Trip Read):**
   - Attempting to read `/users/victim_uid/trips/trip_1` as an authenticated user with UID `attacker_uid`.
   - Expected: `PERMISSION_DENIED`

3. **Cross-Tenant Write (Unauthorized Trip Edit):**
   - Attempting to update `/users/victim_uid/trips/trip_1` as UID `attacker_uid`.
   - Expected: `PERMISSION_DENIED`

4. **Resource Poisoning (1MB path ID injection):**
   - Attempting to write a trip with a massive, malicious document ID.
   - Expected: `PERMISSION_DENIED` (handled by `isValidId`)

5. **Trip Status Bypass (Invalid Enum Value):**
   - Attempting to set `status` to `"InTheCloud"` (unsupported status enum value).
   - Expected: `PERMISSION_DENIED`

6. **Missing Required Fields (Trip name missing):**
   - Attempting to create a Trip without a `name`.
   - Expected: `PERMISSION_DENIED`

7. **Negative or Invalid Numbers in Account Balance:**
   - Attempting to set an account's `balance` to `NaN` or a non-numeric type.
   - Expected: `PERMISSION_DENIED`

8. **Cashbook Entry Tampering (Unregistered Category/Type):**
   - Attempting to write a cashbook entry with `type` `"robbery"`.
   - Expected: `PERMISSION_DENIED`

9. **PII Blanket Read Attempt:**
   - Unauthenticated client attempting to list all trips under `/users/victim_uid/trips/` or via a collection group query.
   - Expected: `PERMISSION_DENIED`

10. **Shadow Field Injection on Account:**
    - Writing an account with un-modeled system field `isSystemApproved: true` to bypass verification limits.
    - Expected: `PERMISSION_DENIED`

11. **Spoofed Audit Trail:**
    - Cashbook entry with a missing `auditTrail` field.
    - Expected: `PERMISSION_DENIED`

12. **Malformed Dates on Trip:**
    - Trip where `startDate` is an object instead of a string.
    - Expected: `PERMISSION_DENIED`

---

## 3. Test Cases (TDD Reference)

The rules prevent all above security breach cases by checking path variables, verifying authentication, and comparing payload keys and types against schema requirements.
